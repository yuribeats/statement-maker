# Design review — SPEC.md §4d house-party auction (not implemented)

Source: `SPEC.md` lines 92-101 at HEAD. No code exists, so every item below is a design risk, not a verified bug.
Checked against the current `Party.sol` / `PartyFactory.sol` to see what the design would have to change.

| # | Severity (design) | Item |
|---|---|---|
| D-1 | High | **Permanent lock if the reserve is never met.** "No end before the first bid … no fallback, ever" plus "Reserve = 100 × the Credits floor at the burn" means a reserve set by one signed reading can freeze the Statement forever: no price vote, no cancel, no expiry, no exit for 80 card holders. Today a high-floor signer error is recoverable (CANCEL + Fixed LIST); under §4d it is not. Recommend at least one of: a reserve that decays after N days, a card-holder vote (60/80) to lower the reserve, or a time-boxed fallback to the ask model. |
| D-2 | High | **Signer compromise (or burner cherry-pick) sets the reserve.** The burner chooses any reading in the 10-minute window (R-6 residual), and the key is shared by every party (R-4). A compromised key sets a reserve of 1 wei (sale at ~0 to the first bidder) or an unreachable reserve (D-1). Bind the reading to the party, and bound it against the last accepted floor. |
| D-3 | Medium | **Settlement must not use `safeTransferFrom` to the winner.** "Anyone settles once: the Statement to the winner". If the winner is a contract that rejects ERC-721 receipt, a `safe` transfer reverts settle forever and the winning ETH and the Statement are stuck. Use plain `transferFrom`, or let the winner pull the Statement. |
| D-4 | Medium | **The party cannot receive the proceeds today.** `Party.receive()` reverts (`Party.sol:617-619`), and `sold`/`perCard` are set only inside `Party.buy`. The design needs a new auction-only payable entry point that sets `sold`, `perCard` and `owed` exactly like `buy`, and it must add bytecode to a contract with 874 bytes of EIP-170 headroom (23,702 / 24,576). |
| D-5 | Medium | **Hostless creation does not fit the factory.** `createParty` makes `msg.sender` the host and requires an opening deposit (`PartyFactory.sol:44-52`, `Party.sol:173,220`). "Hostless, created at deployment" needs a new factory path, and `initialize` must accept no host. |
| D-6 | Medium | **The party's own sale path must be disabled for house parties.** `assemble` sets `ask` from the default price and `buy`/`raiseAsk`/`propose`/`execute` stay callable (`Party.sol:305,339,392,467,478`). If the Statement goes to the auction contract while `ask != 0`, `buy` reverts (the party does not hold the token), but price governance still runs and `countBlocked`/deadlock state accumulates. Gate every one of these on a house-party flag. |
| D-7 | Low | **Outbid refund push.** Push-with-stipend then pull is correct, but the auction must be `nonReentrant` on bid/withdraw/settle, and the accounting invariant (balance == high bid + Σ pull balances) must hold while a refund push re-enters `withdraw`. |
| D-8 | Low | **Anti-snipe extension has no cap.** A bid in the last 5 minutes moves the end by 5 minutes, with a 0.1 ETH step; unbounded in time, bounded only by bidder capital. Acceptable, but state the fixed 0.1 ETH step as intended at every reserve size. |
| D-9 | Low | **Royalty/fee split at settle.** "Split exactly like a sale" — ERC-2981 is being removed from Party and StatementMarket (in progress per the coordinator), so the §4d text should drop the royalty leg to match. |
| D-10 | Info | **Burn liveness depends on the signer.** "Burn: needs a valid signed floor reading" — a signer outage stops every house-party burn; the party then expires and Credits are returned (safe, but the launch stalls). |
